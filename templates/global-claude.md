## Workflow

### План перед кодом
- Для любой нетривиальной задачи (3+ шагов) -- сначала план, потом код
- Что-то пошло не так -- ОСТАНОВИСЬ и перепланируй, не продавливай
- Пиши подробную постановку до начала работы -- меньше двусмысленности

### Субагенты
- Ресёрч, разведку кодовой базы и параллельные куски отдавай субагентам
- Одна задача -- один субагент, главный контекст держи чистым

### Уроки из ошибок
- После КАЖДОЙ поправки от владельца -- запиши урок в tasks/lessons.md
- Правило формулируй так, чтобы ошибка не повторилась
- В начале сессии просматривай уроки по текущему проекту

### Проверка перед «готово»
- НИКОГДА не говори «готово» без доказательства, что работает
- Прогони тесты, посмотри логи, покажи результат
- Спроси себя: «одобрил бы это старший инженер?»

### Элегантность (без фанатизма)
- Для нетривиальных изменений: «есть ли способ проще и чище?»
- Решение похоже на костыль -- переделай
- Простые очевидные фиксы не переусложняй

### Автономный багфикс
- Дали баг -- просто почини: логи, ошибки, упавшие тесты -- сам
- Не проси владельца вести тебя за руку

## Задачи
1. План -- в tasks/todo.md чекбоксами, до начала работы
2. Сверь план с владельцем, потом делай
3. Отмечай выполненное по ходу
4. В конце -- краткий итог: что сделано, что проверено

## Принципы
- **Простота прежде всего:** каждое изменение -- минимально возможное
- **Без лени:** ищи корневую причину, никаких временных заплаток
- **Минимальное вмешательство:** трогай только то, что нужно для задачи

## Superpowers Operating System
Перед задачей проверяю, подходит ли готовый скилл Superpowers. Если да --
использую его:

- `test-driven-development` -- перед написанием кода
- `systematic-debugging` -- при любом баге
- `verification-before-completion` -- перед словом «готово»
